# تطوير المحرر التوثيقي بتقنيات LocalNotaire المتقدمة (بدون ذكاء اصطناعي)

تهدف هذه الترقية إلى تعزيز **الموثق الرقمي** بست تقنيات عملية مستلهمة من نظام LocalNotaire لرفع سرعة ودقة تحرير العقود التوثيقية، مع الحفاظ التام على معمارية المصدر الوحيد للحقيقة (`Single Source of Truth`) ومحاكاة ورقة الـ A4 القانونية بدون أي تدخل للذكاء الاصطناعي.

---

## المراجعات والقرارات المعتمدة

> [!IMPORTANT]
> تم اعتماد القرارات المعمارية والتصميمية التالية بناءً على إجاباتك:

- **القرار المعتمد 1 (البنود الشرطية التلقائية)**: ربط شروط البنود (`condition`) مباشرة بخصائص العقار أو نوع العقد لتفعيل البند أو تعطيله تلقائياً داخل قائمة البنود وورقة الـ A4 فور تغيير خاصية العقار (مثل: عقار في منطقة توسع سياحي، عقار مشاع، ترقية عقارية، أو أراضٍ فلاحية).
- **القرار المعتمد 2 (الاستمارة الديناميكية مع النص المرجعي للبند)**: تقسيم استمارة المتغيرات حسب عنوان كل بند مع عرض النص الكامل للبند كمرجع حي بجانب الحقول (مع تظليل المتغيرات بداخله لحظياً أثناء الكتابة) وقائمة اختيار نوع المتغير (`نص / رقم / تاريخ`).
- **القرار المعتمد 3 (سجل التعديلات التلقائي المفصل)**: تسجيل تلقائي لكل عملية تعديل جوهرية داخل العقد (تفعيل/تعطيل بند، تعديل متغير، تغيير عنوان بند، استيراد أو حفظ) في جدول منظم يعرض (التاريخ والوقت، اسم المحرر، وصف التغيير المختصر، وزر المقارنة المباشرة `Side-by-Side`).
- **القرار المعتمد 4 (تنظيم حقول الوضعية الجبائية والوثائق المشتقة)**: فصل وتنظيم الحقول المغذية للوثائق المشتقة (ملخص النشر، التسجيل، استمارة الضرائب `BR4bis`، الفهرس) في 5 مجموعات مستقلة ومنظمة: **أطراف · عقار · ثمن · وضعية جبائية · فهرس**.
- **القرار المعتمد 5 (تحرير عنوان البند Inline + اختصارات القائمة)**: دعم النقر المزدوج أو زر التعديل السريع بجانب عنوان البند في القائمة الجانبية لتحرير العنوان موضعياً (`Inline`)، مع إضافة زري **«حفظ العقد كقالب مكتب دائم»** و**«إفراغ / إعادة تعيين البنود»** في أسفل قائمة البنود.

## 1. النظرة العامة والمفهوم الأساسي

- **ماذا يقدم التحديث؟**
  1. **محرك البنود الشرطية (`Conditional Clauses Engine`)**: شريط خصائص سياقية للعقد والعقار (مثل: *منطقة توسع سياحي، ملكية مشتركة/حصة، عقار مرهون، بيع بالتقسيط، حق شفعة*) يقوم بتفعيل أو تعطيل البنود الشرطية المرتبطة به تلقائياً في القائمة وورقة الـ A4، مع إمكانية إضافة أو ضبط شرط لأي بند.
  2. **الاستمارة الديناميكية المقسمة بالبنود مع المرجع الحي**: كل قسم في الاستمارة يمثل بنداً من بنود العقد المفتوح، ويعرض في عمود مقابل النص الكامل لهذا البند كمرجع بصري حي يتحدث فوراً أثناء تعبئة الحقول.
  3. **تحرير عناوين البنود Inline وخيارات القائمة السريعة**: تعديل عنوان أي بند مباشرة داخل القائمة الجانبية دون الحاجة للبحث عنه داخل الورقة، مع أزرار سريعة في ذيل القائمة لحفظ هيكل العقد الحالي كقالب مكتب دائم أو إفراغ/إعادة تعيين البنود.
  4. **جدول سجل التعديلات المفصل (`Audit & Version Log`)**: جدول واضح داخل العقد يسجل التاريخ الدقيق، اسم المحرر/الكاتب، ووصف العملية (مثل: *"تعطيل بند: حالة العقار مع التوسع السياحي"* أو *"تعديل متغير: الثمن_رقما"*) مع زر فتح المقارنة جنباً إلى جنب.
  5. **مجموعات الوضعية الجبائية والوثائق المشتقة**: تبويب وتقسيم واضح للحقول القياسية والجبائية في 5 مجموعات (**أطراف، عقار، ثمن، وضعية جبائية، فهرس**) تشمل حقول الوضعية الجبائية المخصصة (*تعيين المبيع، أصل الملكية وثمن الشراء السابق، بيانات البائع الجبائية، بيانات المشتري الجبائية، وتكملة خلف الصفحة*).

- **القيمة المضافة للموثق والكاتب**:
  - تقليص وقت إعداد العقد وتفادي نسيان البنود المرتبطة بوضعية العقار الخاصة.
  - رؤية سياق الجملة الكاملة داخل البند أثناء تعبئة المتغيرات دون إغلاق الاستمارة.
  - تتبع دقيق لكل تغيير يطرأ على العقد عبر جلسات التحرير المتعددة.

## 2. تجربة المستخدم والتصميم البصري

- **مسارات الاستخدام الرئيسية**:
  1. **تفعيل البنود الشرطية بالخصائص السياقية**:
     - في أعلى قائمة بنود العقد، تظهر بطاقة **«خصائص وسياق العقار»** تحتوي على مفاتيح اختيار سريعة (مثل: `منطقة توسع سياحي`، `ملكية مشتركة (وصف تقسيمي)`، `أصل ملكية موروث`، `دفع مؤجل/أقساط`).
     - بمجرد تفعيل خيار `منطقة توسع سياحي`، يتحول البند الشرطي المرتبط به (مثل: *«حالة العقار مع عملية التوسع السياحي»*) من حالة معطل إلى مفعل تلقائياً ويُدرج في موضعه الصحيح داخل ورقة الـ A4، وعند إلغاء الخيار يعود لوضع التعطيل فوراً.
     - كما يمكن للمحرر ربط أي بند بشرط مخصص عبر أيقونة الشرط بجانب البند.
  2. **تحرير عنوان البند Inline واختصارات القائمة**:
     - النقر المزدوج على عنوان أي بند في القائمة الجانبية (أو النقر على أيقونة القلم بجانبه) يحول العنوان إلى حقل نصي موضعي (`input`) يُحفظ بالضغط على `Enter` أو فقدان التركيز، ويُحدّث العنوان في ورقة الـ A4 فوراً.
     - في نهاية قائمة البنود يظهر شريط إجراءات سفلي يضم: **«حفظ العقد كنموذج دائم»** و**«إفراغ / إعادة تعيين البنود»**.
  3. **الاستمارة الديناميكية المزودة بنص البند المرجعي**:
     - داخل الاستمارة الشاملة والشريط الجانبي، يظهر كل بند يحتوي على وسوم `[...]` في بطاقة مقسمة إلى عمودين:
       - **يمين**: حقول المتغيرات التابعة لهذا البند مع محدد النوع (`نص / رقم / تاريخ`).
       - **يسار**: صندوق **«النص المرجعي للبند»** يعرض نص الفقرة كاملاً مع تمييز المتغيرات باللون الأخضر عند تعبئتها والوردي عند بقائها فارغة.
  4. **مجموعات الوضعية الجبائية والوثائق المشتقة**:
     - شريط تبويب منظم يقسم حقول المكتب والوثائق المشتقة إلى 5 مجموعات: `الأطراف` · `العقار` · `الثمن والمالية` · `الوضعية الجبائية` · `الفهرس والتسجيل`، مما يسهل تعبئة بيانات `BR4bis` وملخص الشهر العقاري دون خلطها بمتغيرات نص العقد.
  5. **جدول سجل التعديلات المفصل**:
     - جدول منظم بأعمدة ثابتة (`التاريخ والوقت` | `المستخدم` | `تفاصيل التعديل` | `مقارنة / استعادة`) يسجل التعديلات تلقائياً مع إمكانية تصفية السجل أو فتح المقارنة جنباً إلى جنب لأي نسختين.

- **الهوية البصرية ونظام الألوان**:
  - الحفاظ على الهوية الرسمية الهادئة (`Slate 900`، `Blue 900`، وخلفيات ورقية محايدة `#F8FAFC`).
  - استخدام الأرقام الجدولية (`tabular-nums font-mono`) لجميع التواريخ، المبالغ المالية، والمساحات.
  - الالتزام بعدم استخدام الشارات العشوائية والاكتفاء بنصوص معلوماتية نظيفة مفصولة بـ `·`.

## 3. القرارات التقنية والمفاضلات

- **القرار 1: محرك الشروط السياقية (`Declarative Clause Conditions`)**
  - *النهج المختار*: إضافة خاصية `condition?: { field: string; value: string | boolean; label?: string }` لكل بند في `ContractOutlineClause`، وتخزين قيم السياق في `contractContextFlags` ضمن بيانات العقد.
  - *لماذا*: يضمن بقاء البنود الشرطية معزولة لكل عقد، وتفعيلها أو إخفاءها لحظياً عبر نفس آلية `toggleContractClauseInDOM` دون إعادة بناء المحرر.
- **القرار 2: التسجيل التلقائي المجمع لسجل التعديلات (`Debounced Semantic Audit Log`)**
  - *النهج المختار*: تسجيل الأحداث المباشرة (مثل تفعيل/تعطيل بند، تعديل عنوان بند، تفعيل شرط عقاري) فوراً بوصف دقيق، وتجميع تعديلات المتغيرات أو النص (`debounce`) مع توليد وصف تلقائي يذكر اسم البند أو المتغير الذي تم تعديله واسم الكاتب النشط.
  - *لماذا*: يمنع إغراق قاعدة البيانات بمئات النسخ عند كتابة كل حرف، ويوفر في الوقت نفسه سجلاً مقروءاً ودقيقاً على غرار جدول LocalNotaire.

### ترابط المكونات والبيانات
1. **نموذج البنود الشرطية (`ContractOutlineClause`)**:
   - يضم الحقل الاختياري `condition: { field: string; value: string | boolean; label: string }`.
   - عند تغيير أي خاصية في شريط «خصائص العقار ونوع العقد»، يفحص المحرك جميع بنود العقد التي تملك شرطاً مرتبطاً بهذا الحقل، ويقوم بتحديث حالتها (`enabled: true/false`) في الـ DOM وقاعدة البيانات فوراً مع تسجيل الحدث في سجل التعديلات.
2. **الاستمارة المقسمة حسب البنود مع المرجع الحي**:
   - يتم تمرير نص البند (`previewText` / `contentHtml`) إلى كل مجموعة في `ClauseVariableGroup` ليُعرض بجانب حقول الإدخال مع تظليل القيم المعوضة لحظياً.
3. **حقول الوضعية الجبائية والوثائق المشتقة**:
   - إضافة الحقول الجبائية المتخصصة (*تعيين المبيع الجبائي، أصل الملكية وثمن الشراء السابق، بيانات البائع الجبائية، بيانات المشتري الجبائية، تكملة خلف الصفحة*) وتوزيع جميع الحقول القياسية في 5 تبويبات فرعية منظمة.
4. **جدول سجل التعديلات المفصل**:
   - عرض جدول قياسي واضح يسجل اسم الكاتب الحالي (`clerkName`)، التاريخ والوقت بتنسيق رقمي موحد، ونص التغيير التفصيلي مع زر فتح المقارنة جنباً إلى جنب (`Side-by-Side Diff`).
