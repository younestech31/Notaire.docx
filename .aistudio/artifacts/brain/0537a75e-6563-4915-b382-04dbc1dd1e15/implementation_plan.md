# خطة التطوير التقني المنقحة: نظام البنود الحي (`Single Source of Truth`)، مراجعة استيراد Word، التعديل الموضعي، والأطراف المهيكلة

تعتمد هذه النسخة المنقحة كافة الضوابط المعمارية لضمان استقرار محرر `contentEditable` بنسبة 100% ومنع أي تعارض مع المكونات الحالية، مرتبة وفق الأولويات الخمس المعتمدة.

---

## المرحلة 1: نموذج البيانات ونظام البنود الحي (`Single Source of Truth`)

### 1. قرار معماري حاسم: مصفوفة البنود هي المصدر الوحيد للحقيقة
لتفادي هشاشة `contentEditable` ومشاكل قفز المؤشر عند المزامنة الثنائية المستمرة:
- **`outlineClauses: ContractOutlineClause[]`** داخل العقد هي **المصدر الوحيد للحقيقة (`Single Source of Truth`)**:
  ```ts
  export interface ContractOutlineClause {
    id: string;
    title: string;
    contentHtml: string; // محتوى البند الداخلي (الفقرات والجداول والوسوم)
    enabled: boolean;    // مفعل (ظاهر في الورقة والتصدير) أو معطل (مخفي مع حفظ موضعه ونصه)
    locked: boolean;     // مقفل ضد التعديل بالخطأ (contentEditable="false")
    order: number;       // الترتيب التسلسلي للبند في العقد
    variables: string[]; // الوسوم [...] داخل هذا البند
  }
  ```
- **التمثيل داخل ورقة الـ A4**:
  - كل بند مفعل (`enabled: true`) يُمثل داخل الورقة بعنصر واحد مستقل يحمل ترتيبه الصريح `data-clause-order`:
    `<div class="clause-container" data-clause-id="${clause.id}" data-clause-order="${clause.order}" data-clause-title="${clause.title}" data-clause-locked="${clause.locked}">...</div>`
- **قواعد التحديث الآمنة وحساب موضع الإدراج بدقة حسب `order`**:
  1. **عند الكتابة أو التعديل داخل البند (`onInput`)**: نلتقط العنصر الأب الأقرب `[data-clause-id]` الذي يكتب فيه المستخدم حالياً، ونحدّث حقل `contentHtml` (و`variables`) الخاص بهذا البند فقط داخل مصفوفة `outlineClauses` في الذاكرة وقاعدة البيانات **دون المساس بـ DOM المحرر إطلاقاً**، مما يحافظ على موضع المؤشر وسلاسة الكتابة 100%.
  2. **عند تعطيل بند (`enabled = false`)**: نقرأ آخر نسخة من `innerHTML` لعنصر `[data-clause-id]`، نحفظها في `clause.contentHtml` داخل المصفوفة مع ضبط `enabled: false` والاحتفاظ بقيمة `clause.order` الأصلية، ثم نحذف عنصر الـ `div` هذا فقط من ورقة الـ A4.
  3. **عند إعادة تفعيل بند (`enabled = true`) — حساب موضع الإدراج الدقيق حسب `order`**:
     - نضبط `enabled: true` في المصفوفة، وننشئ عنصر `<div class="clause-container" data-clause-id="${clause.id}" data-clause-order="${clause.order}">`.
     - نبحث داخل المحرر عن جميع عناصر `.clause-container[data-clause-order]` الحالية، ونجد **أول عنصر مفعل تكون قيمة `Number(el.dataset.clauseOrder) > clause.order`**:
       - إذا وُجد هذا العنصر التالي: نستخدم `editorEl.insertBefore(newClauseDiv, nextActiveEl)` لإدراجه قبله مباشرة بدقة متناهية.
       - إذا لم يوجد بند مفعل بتسلسل أكبر (أي أنه البند الأخير أو الوحيد): ندرجه في نهاية منطقة البنود (`appendChild`).
     - هذا يضمن استحالة حدوث أي قفز أو تداخل حتى لو تم تعطيل عدة بنود متفرقة وإعادة تفعيلها بأي ترتيب عشوائي.
  4. **عند إعادة الترتيب بالسحب والإفلات (`Drag & Drop`)**: نعيد ترقيم `order` (`0, 1, 2...`) لكافة البنود في مصفوفة `outlineClauses`، ونحدّث `data-clause-order` وترتيب عناصر `div.clause-container` المفعلة داخل ورقة الـ A4 بنفس التسلسل دون فقدان أي محتوى.
  5. **عند قفل/فك قفل البند (`locked`)**: نبدّل خاصية `contentEditable` و`data-clause-locked` على عنصر `div.clause-container` المعني فوراً لمنع أي تعديل أو حذف بالخطأ.
  6. **القفز المباشر (`Direct Jump`)**: النقر على البند في القائمة الجانبية يمرر الورقة مباشرة إلى `[data-clause-id]` مع وميض بصري هادئ.

### 2. مكتبة البنود الفارغة افتراضياً + حزمة قياسية منفصلة عند الطلب
- تظل مكتبة البنود في الكود الأساسي (`lib/storage.ts`) **فارغة افتراضياً (`[]`)** ليبقى التطبيق خفيفاً ونظيفاً.
- تُفصل الحزمة القياسية للبنود التوثيقية الجزائرية في ملف مستقل (`lib/standard-clauses-pack.ts`) لا يتم تحميله إلا ديناميكياً (`await import('./standard-clauses-pack')`) عندما ينقر المستخدم يدوياً على زر **«استيراد الحزمة القياسية الاختيارية»**.

## المرحلة 2: تحديث استيراد Word لاستخراج البنود مع مراجعة يدوية تفاعلية

لأن ملفات العقود القديمة بصيغة Word قد لا تتبع نمط عناوين موحداً:
1. **الاستخراج الأولي المقترح**: يقترح محرك `importNotaryDocxFile` تقسيم المستند إلى بنود بناءً على الأسطر التي تبدأ بـ `#` أو الفقرات العنوانية القصيرة الغامقة (مثل: `أولاً: التعيين`، `البند الأول:`، `الثمن:`، `أصل الملكية:`).
2. **واجهة المراجعة اليدوية التفاعلية في `DocxImportPreviewModal` قبل الاعتماد**:
   - تعرض قائمة البنود المكتشفة مع معاينة فقرات كل بند، وتتيح للموثق قبل الضغط على «اعتماد وإدراج في المحرر»:
     - **تعديل عنوان البند يدوياً** في مكانه.
     - **دمج بند مع البند السابق («دمج مع السابق»)** إذا اعتبر النظام سطراً غامقاً عنوان بند بالخطأ.
     - **فصل بند إلى بندين («فصل هنا كبند جديد»)** عند أي فقرة داخل البند.
     - **خيار الاستيراد كبند واحد متصل** إذا رغب المستخدم بعدم التقسيم.

## المرحلة 3: التعديل الموضعي العائم للمتغيرات (`Inline Variable Popover`)

بعد استقرار بنية حاويات البنود `div.clause-container`:
- عند النقر على أي وسم `.smart-tag` (`[متغير]` أو `{{متغير}}`) داخل ورقة الـ A4:
  - تظهر نافذة عائمة صغيرة (`components/InlineVariablePopover.tsx`) متموضعة فوق الوسم مباشرة.
  - تتيح:
    - كتابة أو تعديل قيمة المتغير فوراً مع تحديث جميع مواضعه في العقد لحظياً.
    - تبديل نوع المتغير (`نص` / `رقم` / `تاريخ`) مع معاينة التفقيط الجزائري بالحروف وزر «إدراج بالحروف».
    - زر «فتح الاستمارة الكاملة» للانتقال إلى نافذة المتغيرات الشاملة عند الرغبة.

## المرحلة 4: بطاقات الأطراف المتعددة (`role` + `index`) والربط التلقائي بالوسوم

1. **نموذج `ContractPartyCard` المهيكل**:
   ```ts
   export type NotaryPartyRole = 'بائع' | 'مشتري' | 'موكل' | 'وكيل' | 'واهب' | 'موهوب' | 'أخرى';

   export interface ContractPartyCard {
     id: string;
     role: NotaryPartyRole;
     customRoleLabel?: string; // عند اختيار 'أخرى' (مثل: شريك، مقاسم، مؤجر)
     index: number;            // 1، 2، 3... للسماح بـ بائع 1، بائع 2
     fullName: string;
     birthDate: string;
     birthPlace: string;
     filiation: string;        // ابن فلان وفلانة
     nationalIdNin: string;    // رقم التعريف الوطني
     idCardDetails: string;    // رقم وتاريخ وجهة صدور بطاقة الهوية
     address: string;
     legalRepresentative?: string;
   }
   ```
2. **الربط التلقائي بالوسوم (`Automatic Variable Binding`)**:
   - أي تعديل في بطاقة الطرف (أو استدعاء طرف من دفتر الأطراف المحفوظين) يحدّث تلقائياً قاموس `fieldValues` للعقد الحالي بجميع الصيغ المتوافقة:
     - صيغة الصفة والرقم: `[البائع_1_الاسم]`، `[البائع_1_الرقم_الوطني]`، `[البائع_1_العنوان]`...
     - صيغة النقطة أو الشرطة بدون رقم (للطرف رقم 1 من كل صفة): `[البائع.الاسم]`، `[البائع_الاسم]`، `[المشتري.الاسم]`، `[المشتري_الاسم]`...
     - صيغة الطرف الأول / الثاني القياسية للوثائق المشتقة: `[الطرف_الأول_الاسم]`، `[الطرف_الثاني_الاسم]`...

## الملفات المستهدفة حسب مراحل التنفيذ
1. **`lib/types.ts`**: تعريف `ContractOutlineClause` (مع `enabled`, `locked`, `order`) و`ContractPartyCard` (مع `role`, `index`) وتحديث `SavedDocument` و`DocxImportResult`.
2. **`lib/standard-clauses-pack.ts`** *(ملف منفصل يُحمّل عند الطلب)*: حزمة البنود التوثيقية القياسية الاختيارية.
3. **`lib/storage.ts`**: تفريغ `DEFAULT_NOTARY_CLAUSES` افتراضياً لضمان خفة التطبيق.
4. **`lib/editor-utils.ts`**: دوال إدارة `outlineClauses` كمصدر وحيد للحقيقة (التحديث الجزئي لـ `contentHtml` عند الكتابة، الإخفاء/الإظهار الفوري مع حساب موضع `insertBefore` الدقيق حسب `data-clause-order`، السحب والإفلات، وقفل البند).
5. **`lib/docx-engine.ts`**: استخراج البنود الأولية عند استيراد Word، وتصدير البنود المفعلة فقط عند إنشاء ملف Word.
6. **`components/InlineVariablePopover.tsx`** *(ملف جديد)*: النافذة العائمة فوق الوسم للتعديل السريع.
7. **`components/SidebarWorkspace.tsx`**: واجهة البنود الحية (Checkbox، Drag & Drop، قفل، قفز مباشر، وزر استيراد الحزمة القياسية الاختيارية) + واجهة بطاقات الأطراف المتعددة (`role` + `index`).
8. **`components/SmartModals.tsx`**: واجهة المراجعة اليدوية للبنود المستخرجة من Word (دمج/فصل/تعديل العنوان) في `DocxImportPreviewModal` + وضع `Side-by-Side Diff` في `VersionDiffModal`.
9. **`components/NotaryEditorApp.tsx`**: ربط المراحل الخمس داخل المحرر الرئيسي.
